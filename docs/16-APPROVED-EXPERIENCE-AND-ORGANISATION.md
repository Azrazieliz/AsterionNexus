### Layout applicability (strict)

- Gallery follows Core/Samsung Gallery-like immersive, near-edge-to-edge large real image/GIF previews, masonry/adaptive proportions and compact controls. Prefer original aspect, sensible crop policy and full image on open. Animate visible GIFs subject to resource limits.
- Videos are separate from Gallery; large real video previews, muted autoplay of the centered visible preview (one active preview, stop/pause out of view, obey device resource and accessibility preferences). Tap transitions into **actual fullscreen playing video**, retaining context and playback position. Native player exposes only relevant controls, full seeking, audio/subtitles and existing supported playback features.
- Books/comics and suitable folders/collections: horizontal swipeable cover-flow/flying preview, prominent selected real cover or characteristic content image occupying approximately 85–95% of available viewing area (subject to aspect ratio and safe insets), with neighboring previews partially visible when feasible. Tap opens reader/contents. No chapter archive tiles for a newly acquired complete comic. Preserve real reader modes.
- Audio uses artwork and playback, documents use page/content preview, 3D uses genuine interactive model/representative preview when supported, archives/packages expose actual contents/metadata; every type adapts instead of being forced into a photo grid. Use honest format fallback when preview cannot be generated.
- Collections obtain representative covers from actual content. Offer continue-reading/watching from existing progress and related content through canonical series, character, creator and project relationships.
- Swipe horizontally through context submenus; bottom navigation selects major areas. Within a focused cover flow, gallery or reader/player, local gestures take priority. Preserve Android edge navigation, vertical scrolling, zoom and selection. Provide accessible tap equivalents, restore scroll/selection on Back, and avoid wrapping submenu swipes across major areas by default (delegated design choice).
- Media rating is **file metadata on opening the file** (viewer/details, shared item action); it is not a permanent navigation destination, Organising submenu, Review tab or independent rating module. Keep controls discreet and available across rateable file types.

## 2. Canonical command ownership and deduplication

Use one canonical destination/module registry, one file identity registry and one durable job/transfer system. Each action has one semantic ID, implementation, permission scope, execution path and state. A contextual shortcut is allowed only if it invokes that same canonical action, not another implementation or independent queue. Do not repeat the same action on the same screen in several toolbars/cards, duplicate module directories, or create a separate folder hierarchy per donor. No duplicate Search, Sync, Backfill, Review, Ratings or Transfers engines. Cross-view shortcuts preserve context and route to the canonical destination/state.

Preserve all applicable donor commands and semantics even where presentation is consolidated: creator following, subscription, live sync, independent backfill and cursors, source/album enumeration, exact selected acquisition, complete galleries, torrent selection/verification, retries, pause/resume/cancel, history, cloud accounts, streaming/cache/pins, readers/bookmarks/progress, Fusion tagging/knowledge/corrections/learning, organisation and rollback, offline translation, editing, corruption repair, smart collections, direct signed partner actions and optional Control orchestration. Never infer sync completion from backfill or vice versa. A single discreet background-activity indicator links to canonical jobs; separate processing and transfer evidence remain truthful. Do not lose donor functionality while fusing equivalent systems.

## 3. Search, acquisition and TeraBox

Downloading Search/Suggestions/module discovery results are genuine previews of the exact selected downloadable item or complete collection. A tap starts verified acquisition directly, not a browser redirect, external link, or download of the thumbnail. If a legal/authorized source requires authentication, file subset selection, or another necessary interaction, stay in the native acquisition flow and surface only that required action; no browser link is a substitute for acquisition. Existing local/cloud library search results open the existing item rather than download a redundant copy; federated search retains source scope/provenance and privacy. Do not claim availability until exact bytes and destination are verified.

Separate download types using one module registry and type-aware queues/views: artwork, cosplay, videos (series/films), books/comics, 3D assets, games/resources, audio, archives/other files and torrents as appropriate. Retain all original source adapters and supported subtypes; do not make a second directory merely for provider-specific options. Result cards are real media previews adapted to type. Album selection acquires all expected originals; comic selection acquires the complete title, not a chapter-only sample. Suggestions use actual owner preferences, ratings, related content, missing titles/volumes and authorized source scope; clicking a suggested downloadable item uses the same acquisition path.

**TeraBox is the Library and permanent default destination for every acquired media type**, with multiple isolated account namespaces. Present them in one aggregate view with contextual account filters; no separate top-level Cloud tab. Local storage is primarily metadata/indexes/models, previews/range cache, temporary verification/processing and explicitly pinned offline items. Stage, verify, classify/rename/organise, publish to TeraBox, verify remote identity/bytes as supported, index and reopen. Preserve original bytes, provenance and source assets as required. Existing owner-confirmed cleanup policy still applies; no silent deletion of a sole copy or unverified original. Bounded disposable caches may be evicted under policy; pinned files stay. Use actual remote evidence and never fake remote checksums. Treat failed remote publish as incomplete, with resumable state.

Do not invent identity, transformation, series or creator. Keep source names, relationships and full metadata regardless of display filename. Preserve dependency-sensitive internal package paths, references, manifests, textures and sidecars. Do not overwrite another item; use stable counters or review collisions and journal reversible changes. All media may be automatically reorganised within authorized storage following owner patterns; legacy migration itself remains non-destructive and must not silently bulk-move ungranted originals. ## 5. Two separate learning signals

Review is a correctness/automation confirmation inbox: uncertainty in identities, taxonomy, routing, conflicts, automated edits, integrity and other actual decisions needing owner confirmation. Correct, confirm, defer, undo and eligible batch actions refer to canonical events. A genuinely empty queue differs from unavailable/uninitialized data. Ratings are the owner's subjective liking (0–100 per opened file as canonical metadata, including other relevant media). Ratings drive preference learning for downloading/suggestions, content triage/review candidates and authorized partner recommendations; they are not review decisions, objective quality labels, content classification, or identity correction. Keep manual rating authoritative and durable across rescans, cloud moves, migration and restoration. Learn automatically from both signals using separate labels/objectives, shared validated infrastructure where appropriate; do not let a low rating unlearn a correct character identity. Below-25 discard suggestions remain reviewable suggestions only, never automatic deletion. Never add a standalone ratings module or duplicate per-file rating stores.
